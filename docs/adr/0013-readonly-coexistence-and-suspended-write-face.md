# 与既有 mihomo 的关系收窄为**只读共存**;控制面写这一族**暂时停用**

> **2026-08-18 修订**（[ADR 0014](0014-mihomo-embedded-subprocess.md)）：本 ADR 的「只读共存」立场**原样并入**托管模式的 `observe` 档，继续有效；「共存阶梯」词汇退场（`reuse_binary`/`managed_install` 两档由 embedded 子进程取代）；`mihomo_foreign_instance_running` 拒绝与 `--isolated` 逃生门被「首启双选流 + 并跑口径」取代（0014 第 3/7 条）。写面九条维持摘注册；文末预告的节点合并 CLI 方向不变、地位上升。

2026-08-12 用户裁定,两件事一起做:

1. **本机已有在跑的 mihomo → 只读它的状态,不去接管。** 共存阶梯的第一档「收编运行中的实例」
   (`adopt_instance`)整档废除。
2. **经 external-controller 改 mihomo 的那一族能力暂时关闭**——切模式、选节点、测速、改可调项、
   订阅五条。**「读一下 mihomo 状态就够了;mihomo 应该让用户自己用 agent 去配置。」**

第 2 条明写「暂时」,所以实现形态是**摘掉能力注册,不删代码**;第 1 条是永久收窄,契约与代码一并清掉。

## Context

- **触发点是真机验收里的一句观察**:面板的菜单栏壳把整套代理配置摊在菜单里(模式三项、逐组逐节点、
  测速、订阅四组),而**小白用户在那个界面里配不明白**——他不知道 rule 与 global 的差别意味着什么,
  也不知道「激活订阅」会把整份配置换掉。给一个看不懂的人一堆能改坏网络的开关,不是易用性。
- **与北极星同向**:本项目的插件北极星是「agent 现场写插件」([ADR 0005](0005-agent-first-interaction.md)
  把 CLI 定为主交互面)。mihomo 的配置是一份 YAML,而**改 YAML 恰恰是 agent 最擅长的事**。
  与其在 GUI 里造一套永远追不上 mihomo 表达力的开关,不如把配置交还给用户与他的 agent,
  a2 只负责「读得出来、说得清楚」。
- **收编档在实践中的样子**:06 票设计的收编档是「探得通就记一笔,此后经 REST 接管配置面」。真机上
  用户那份 mihomo 连 `external-controller` 都没写(自建单节点配置),压根收编不了;而**能**收编的
  那种配置,恰恰是主人自己在打理的——a2 插一脚进去只会制造「两个主人」。
- **一处被顺带发现的事实**(与本决策同源,记档):`a2 mihomo install` 在**已就位**状态下写了新配置
  却不重启也不重载,配置停在盘上不生效。这与 07 票 `reloadConfig` 不带 `force=true` 是同一族缺陷,
  归待开的那张重载票,不在本 ADR 范围内。

## Decision

1. **共存阶梯从三档收成两档**:`reuse_binary`(只读复用盘上的二进制)与 `managed_install`
   (按锁定版下载)。`adopt_instance` 与它的落盘记录 `adopted.json` 一并退场——**内核不再往盘上写
   任何「我盯着别人哪个实例」的状态**。
2. **别人的实例只进报告面**。`a2 mihomo status` 照旧如实报出它的地址、版本、能力位与来源配置
   (`instance.owner = "foreign"`),`a2 proxy status` 照旧读得到它的模式/端口/分组。变的是:它不再
   影响档位裁定,也不再有任何一条写路径通向它。
3. **未就位时撞见别人在跑的实例 → 结构化拒绝、零改动**(`mihomo_foreign_instance_running`,退出码 5)。
   既不收编,也**不默默在人家旁边再起一份**——机器上要不要同时跑两份 mihomo 是有代价的决定
   (两套入站端口、两份配置),该由人来做。**逃生门是显式的 `a2 mihomo install --isolated`**。
   a2 **已**就位时不走这道闸(维持现状,避免检测结果反复横跳把数据面掀了)。
4. **存活监督只盯自管那一份**。收编记录没了,「我盯着的那个实例死了」这句话也就没有了主语;
   反复探一个我们既不负责拉起、也不负责配置的进程,只会给人一份看着像「我管着它」的假报警。
5. **写面九条摘掉注册**:`proxy.config.set`、`proxy.mode.set`、`proxy.node.select`、
   `proxy.latency.test`、`proxy.subscription.{list,add,update,activate,remove}`。
   - **摘的是注册,不是代码**:handler 与它们的断言原地保存,恢复 = 从
     `capability/proxy.ts` 的 `DISABLED_CAPABILITY_IDS` 里删一行。
   - `proxy.latency.test` 的 HTTP 谓词虽是 GET,但它**命令 mihomo 真去发一轮网络请求**,
     算控制不算读状态,一并停。
   - **只读的一条不停**:`proxy.status` / `mode.get` / `groups` / `config.get` / `supervision`。
   - `proxy.system.{enable,disable,status}` **不在范围内**:它改的是**系统**设置,对 mihomo 只发一个
     `GET /configs` 取端口。系统代理开关是面板留下的唯一开关,也是小白唯一需要的那个。
6. **「关闭」的协议含义就是「不在 `capabilities list` 里」**,不另设「存在但拒绝」的半态。
   agent 靠 list 发现能力,发现不到就不会调;面板每个菜单项本就写着 `has("<id>")` 守卫,于是菜单项、
   CLI 别名、面板按钮**自动一起消失**,壳侧一行代码都不用改([ADR 0004](0004-capability-registry-sole-call-surface.md)
   「注册表是唯一调用面」在这里第一次收到回报)。
7. **测试的挂起判据必须读生产常量**。停用能力的断言用 `skipIf(DISABLED_CAPABILITY_IDS.has(id))`
   挂起,而不是手写 skip——恢复注册的那一刻覆盖自动回来,没有人需要记得同时改测试。
   面板侧同理分成两份清单:`capabilities`(渲染器覆盖面,**保留**停用能力的描述符,那部分渲染逻辑
   一行没删,必须继续被验)与 `liveCapabilities`(对账用,= 全集减停用),旗舰 e2e 拿真内核快照对后者。

## Consequences

- **面板菜单剩下三块**:状态行(模式/节点/端口,只读显示)、系统代理开关、服务安装/升级/卸载。
  04 票那份「六项用户操作」的产品承诺**当前只剩两项有能力兜底**(系统代理开关、基础状态);
  覆盖面断言的分母因此跟着活着的能力走(`actions=2/2`),而不是硬编码 6——恢复注册时它自己涨回去。
- **`mihomo_below_floor` 失去全部产出方,一并摘除**。它原先只由收编档产出(「收编对象不达地板」);
  复用档不达地板走的是 `result.fallback` 那条**成功**路径,不是错误。留一条永远不会出现的错误码,
  等于让 agent 为一个不存在的分支写代码。
- **旗舰 e2e 的 dangerous 活体样本改用 `demo.wipe`**。三层仲裁那三幕原先骑在
  `proxy.subscription.add` 上——它随写面停用了。`demo.wipe` 的风险档与仲裁路径与真能力完全一样
  (handler 不做任何实际动作),覆盖不损失;恢复订阅时换回去是三行。
- **订阅数据不动**。停的是能力注册,catalog 与物化配置照旧躺在 `~/.a2/mihomo/subscriptions/`,
  `resolveDesiredConfig` 也照旧会把当前激活项渲染进自管配置——**已经在用的机器不会因为这次收窄
  而被改回 `MATCH,DIRECT`**。
- **门禁那条红线自查顺带修好**(2026-08-12 实测):`R-1` 原判据是「真实 `~/.a2` 不存在」,而用户真机
  验收装了一份之后它**永远红**。红线的本意不是「这台机器不许有 a2」而是「门禁不许碰用户那一份」,
  所以改成基线比对(跑前落时间戳标记,跑完 `find -newer`)。新判据**更严**:原判据对「home 本来就在、
  被门禁改了」完全看不见。
- **接下来要补的那件事**:配置权交还给用户与 agent 之后,「把机场订阅里的节点弄进 mihomo 配置」
  变成一件需要工具的事。方向已定——一条 **CLI**,把订阅里的节点抽出来合并进一份 mihomo 配置,
  **默认打到 stdout,`--out` 才落盘**(a2 不动用户的配置文件,除非人显式指路)。设计另议,不在本 ADR。
