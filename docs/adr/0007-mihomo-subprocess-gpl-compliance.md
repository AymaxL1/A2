# mihomo 集成：独立子进程红线、外部安装不随包分发、GPL 义务落 `a2 about`

代理插件把 GPL-3.0 的 mihomo 内核作为**外部程序**调用。集成红线（不变）：内核只以**独立子进程**运行，控制面只走其外部接口（REST API / 配置文件），**永不进程内链接**（含 c-archive/cgo 静态链接）——这使我们的程序与 mihomo 构成 FSF 意义上的 separate programs / mere aggregation，本项目代码得以保持闭源（中高确定性；ClashX Meta 因静态链接被迫转 AGPL 是反例）。

> **2026-08-04 修订**：mihomo 改为**不随任何分发物打包**（用户裁定），义务面从「分发合规」收缩为「调用外部程序」；**内核重签校验废除**；关于页降级为外部程序声明，并新增 `a2 about` + 随包静态文本作为不依赖 UI 的必有落点；独立子进程红线**保留并泛化**为插件通用边界。改动清单见文末[修订记录](#修订记录2026-08-04)。

## Decision

- **红线（不变）**：mihomo 只以独立子进程运行，控制面只走 REST API / 配置文件；**永不进程内链接**。此判据是「是否同一可执行文件」，**与实现语言无关**——内核换成 TS（[ADR 0010](0010-ts-kernel-bun-runtime.md)）后逐字适用。
- **红线泛化**：该边界升为**插件通用边界**——一切插件都是进程外子进程，能力只经协议白名单（[ADR 0011](0011-plugin-exec-protocol-loading.md)）。
- **不随包分发**：mihomo **不进任何我们分发的产物**（bin、安装脚本包、`a2-panel.app` 皆不含）；获取走我们提供的安装脚本，从官方渠道拉取。我们对 mihomo 的职责收敛为四件事：**脚本化安装、配置管理、开机自启、存活检测**。
- **托管与监督**：脚本安装的 mihomo 挂**自己的** `com.a2.*` launchd/systemd unit——开机自启与崩溃重拉归系统 supervisor，内核只做配置 + reload、存活探测、经 launchctl/systemctl 启停。**数据面不随控制面起落**：内核崩溃或升级不断用户网络。
- **共存 = 检测并优先复用**（用户明确解除了产品层「不接管用户 mihomo」的约束）：①检测到运行中实例（external-controller 可达）→ 经 API 接管配置与监督，但**进程生死仍归其原托管方**，实例死了只报警 + 指引，不越权重拉；②仅检测到二进制 → 只读复用二进制，配置/数据/unit 全套自建；③全无 → 脚本安装，版本按我们的发布元数据锁定。兼容性不达标回退隔离安装；**升级永远是显式命令**，不做静默更新。
- **GPL 义务落点**（义务面收缩为「调用外部程序」后仍必须履行，裁决序里法律义务在 agent-first 之上）：
  - **`a2 about` 子命令 + 随包静态文本**是**必有落点**——不依赖任何 UI，Linux 无头端与 mac 终端一样能读到；
  - 内容 = 声明本程序调用外部 GPL-3.0 程序 mihomo、其许可与源码获取指引、我们的安装脚本从何处拉取何版本；
  - 菜单栏壳的「关于」界面降级为**同一份静态文本的可选呈现面**，不再是义务的唯一落点。
- **废除项**：**内核重签校验废除**（它的前提是「我们分发 mihomo 二进制并对其重签」，该前提随不随包分发一并消失）；随应用锁版、升内核 = 发应用更新的模型作废，改为上述显式升级命令。

## Consequences

- 换取：不分发 GPL 二进制后，义务面显著收窄（无重签、无随包锁版、无自建内核分发通道）；用户的 mihomo 版本不再被我们的发版节奏绑架。
- 代价：安装链多一步网络获取（无网络/官方渠道不可达时安装失败，须有明确指引）；mihomo 版本不再是「可测的固定配套」，兼容性下限检查成为内核的常设职责。
- 红线永久排除进程内集成的体积/性能优化路径——这条不因语言、不因分发形态而松动。
- 依据：`.scratch/v1-mac-recharter/issues/02-mihomo-integration-survey.md`、[mihomo-integration.md](../research/mihomo-integration.md)（原始 GPL 分析）；本次修订依据 `.scratch/kernel-bin-recharter/issues/12-mihomo-distribution-form.md`、`.../04-kernel-boundary-process-model.md`、`.../08-adr-roadmap-revision.md`。

## 修订记录（2026-08-04）

原文（2026-07-28）的模型是「mihomo 随应用打包 + 锁版 + 构建链统一重签 + 关于页附 GPL 文本」。2026-08-04 用户主动裁定「mihomo 还是不打进我们的包了，我们只提供脚本去安装，改配置，开机自启，代理存活检测等功能就好了」，连带修订如下：

1. **分发形态**：随包 → **外部安装**（脚本从官方渠道获取）。
2. **义务面**：分发合规 → **调用外部程序**。我们不再分发 GPL 二进制，义务收缩为如实声明 + 源码获取指引。
3. **义务落点**：关于页（唯一落点）→ **`a2 about` + 随包静态文本**为必有落点，关于页降级为可选呈现面。理由：UI 已降为可选（[ADR 0008](0008-kernel-bin-ui-optional.md)），把法律义务挂在可选组件上不成立。
4. **内核重签校验废除**：v1-core-proxy 15 票已实现的重签校验随其前提消失而作废（该票的 GPL 关于页部分降级保留）。
5. **锁版模型作废**：随应用锁版 → 安装脚本按发布元数据锁定版本 + 显式升级命令。
6. **红线泛化**：「独立子进程、永不进程内链接」从 mihomo 专条升为**一切插件的通用边界**（[ADR 0011](0011-plugin-exec-protocol-loading.md)）。
7. **不变的**：红线本身、闭源姿态的法律论证、「若要零风险可把代理插件本体开源」这条备选。
