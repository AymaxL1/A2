# 09 — 终裁:是否翻案 ADR 0002 切换 Electron+TS(HITL)

Type: grilling
Status: resolved
Blocked by: 01, 02, 03, 04, 05, 06, 07, 08

## Question

在 01–07 的事实与 08 的澄清之上,当面终裁:V1 是否翻案 ADR 0002,从 Swift 原生切换到 Electron+TS(即执行当年保留的回退候选)?

裁决须直面的三层:

1. **与旧硬门框架的关系**:路线图写明回退裁决「一次,之后不回头」且三条硬门均未触发;本次是硬门之外的新动机(进度/工具链)。翻案要么承认新动机构成新判据,要么明确这是重画目的地——写进裁决文,别含糊。
2. **两条路线的解阻塞对照**(01 票结论表):切 Electron = 装 Node(分钟级)+重写 S1/S2 资产+ADR/路线修订;留 Swift = 装 Xcode(一次性,用户操作)+既有资产全保。裁决本质是「一次性环境成本」vs「结构性重写成本」的取舍,叠加 05 票的自读兜底/测试闭环收益与 04 票的常驻/维护税。
3. **裁决输出**(参照 03 票 Answer 的格式):栈决定+可直接转 ADR 的理由;若翻案——ADR 0002 的翻案文方向、0001 是否连动、路线图/Phase 0 spike 重排方向、S1/S2 资产处置、原调研文档废弃章节复活清单;若维持——Xcode 安装仪式排入待办、本图归档、Electron 材料标注「已评估,维持原判」。

本票在明天与用户的对话中解决;不 AFK 裁决。

## Answer

**裁决(2026-07-28,用户当面确认):不翻案。ADR 0002(Swift 原生)维持;V1 期内技术栈问题就此封卷,不再重开。**

按 Question 要求的三层逐一交代:

### 1. 与旧硬门框架的关系

本次 electron-recon 定性为:**三条回退硬门之外、由新动机(进度/工具链/通用性)触发的一次性重评**,不是硬门触发,也不是重画目的地。七张 AFK 票查实后,重评结论为**维持原判**。V1 期内两条重开路径均已穷尽——硬门三战三捷在前(S1/S2/S3 全过),新动机重评在后(本图),此后不再受理栈问题;路线图「裁决一次,之后不回头」的承诺经此一次破例后重新封死。

### 2. 解阻塞对照的取舍

用户澄清(08 票):要消除的是**这一次环境排队阻塞**,不是长期拒绝苹果工具链——「接受装 Xcode,只是不是今天」。故取舍为:**接受一次性环境成本**(装 Xcode,挂 Phase 0 基建前置待办,不排今天;期间推进零 Xcode 纸面工作),**拒绝结构性重写成本**(S1/S2 资产重做、ADR/路线修订、3–5 倍常驻内存、8 周升级节奏)。

叠加的实质技术锚点(A5):**「宠物窗压在全屏 App 之上」定为硬需求**——Swift 侧 S1 已实测通过(fullScreenAuxiliary);Electron 侧同需求为 2017/2022/2023 三度报告、均 wontfix 类关闭的问题(02 票),大概率过不了 S1 自己立下的参照线。维持原判由此不只是环境成本账,还有硬技术依据。

通用性动机结清见 08 票 Answer:(a) 开发环境诉求以一次性 Xcode 了结;(b) Windows 诉求重新确认 ADR 0001 旧承诺「届时含核心重写」,明文放弃 Electron 的 Windows 折扣。0001 不连动。

### 3. 裁决输出(「若维持」分支)

- **Xcode 安装仪式**:排入待办,作为 Phase 0 基建(SPM 骨架/XcodeGen/check.sh/最小签名仪式)的前置条件;用户择时执行,不阻塞纸面工作。
- **本图归档**:九票全部 resolved,地图标注「已评估,维持原判」;worktree 分支 merge 进 main 后删除,研究文档五份、E1 spike、地图与票全部保留归档。
- **Electron 材料标注**:`docs/research/electron-recon/` 加 README 声明终裁结论;本图头部同标。
- **B3(vfsoverlay)**:过渡期保留(仅 spike 级直编),装完 Xcode 后退役,S1/S2 run.sh 改回标准 `swift build`。
- **B4(Tauri)**:维持出局。
- **E1 43.x 重跑**:免——不切栈,重验无意义。
- **B1/B2「若切」条款**:失效(Node SEA 结论与 S1/S2 资产处置建议归档备查,不执行)。
- **ADR 状态**:0001–0007 由 proposed 置为 accepted(Phase 0 验收 + 本次重评双重确认);0002 附本次重评记录。
- **签名(A4)**:无 Apple Developer 账号、暂无对外分发计划;免费 dev 签名挂装 Xcode 后,付费账号 + Developer ID 挂 Phase 3 前置。
