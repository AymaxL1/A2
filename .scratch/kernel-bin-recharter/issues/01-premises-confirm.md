# 01 — 前提确认:其他端野心、在飞工作处置、UI 可选的强度

Type: grilling
Status: resolved

## Question

本图 destination 取自用户 2026-08-04 一句话开图原话(「主逻辑完全不依赖 UI;内核完全是 bin,通过 CLI 使用;agent first 是最高宗旨;UI 不是必须的了,Mac 先用 Swift,其他端先不做 UI;这是一次大重构」),四组前提须经面试钉死——其余决定票全部押在上面:

1. **「其他端」的真实含义**(牵 [ADR 0001](../../../docs/adr/0001-mac-only-platform-boundary.md)/[0002](../../../docs/adr/0002-swift-native-stack.md)):内核跨端(Linux/Windows 上经 CLI 无 UI 使用)是**当下承诺**还是**远景愿望**?
   - 若当下承诺:内核语言要不要重议(Swift on Linux?换语言重写?)——若要,从雾区开专票,04 票等它。
   - 若远景:内核仍 Mac-only + Swift,仅在边界设计上不主动封死跨端可能?
2. **在飞工作处置**:`worktree-v1-tickets-11-16` 待合分支、17 票(swift-testing 迁移,分支上已有提交)、5 条人工项(Phase 1 出口两条真机实测 + 签名仪式人工项)与本重构的先后:
   - (a) 先收口 Phase 1(合并 + 17 + 人工项)再重构;
   - (b) 合并已有工作,但 Phase 1 出口判据随重构重写,人工项顺延;
   - (c) 立即重构,在飞工作按新架构折算。
3. **「UI 不是必须的」的强度**:无 GUI 是**一等公民运行形态**(内核 + CLI 可独立分发、全功能可用,含 dangerous 流程)还是「GUI 默认随附、逻辑上解耦即可」?这直接决定 05 票(dangerous 确认重设计)的解空间大小。
4. **agent-first「最高宗旨」的裁决权重**:与安全确认(agent 可自批的风险)、GPL 义务履行、人类用户体验冲突时,agent-first 压倒到什么程度?给 05/06 票一个可执行的排序原则。

顺带核对本图 Destination 措辞是否如实转写了用户意图(后台开图,未经现场面试)。

## Answer

四组前提于 2026-08-04 现场面试钉死(每问先给推荐、用户裁决;第 1 问用户推翻推荐):

1. **「其他端」= 当下承诺,内核语言全重议**:内核跨端不是远景而是当下承诺;语言重议全开(Swift/Go/Rust 都在桌上),ADR 0001/0002 重开。端范围(Linux/Windows 谁入列)不在前提层预裁,交给语言重议票连同语言一起给结论。→ 已开 [09 调研:跨端内核的语言与平台成本盘点](09-kernel-language-landscape.md) + [10 决定:内核语言与跨端范围](10-kernel-language-decision.md);04 票加等 10。
2. **在飞处置 = (b) 合并 + 重写出口**:先合并 `worktree-v1-tickets-11-16`(11–16 票 + 17 票已提交工作)保住已完成价值;Phase 1 出口判据随重构重写(落 08 票路线图修订);5 条人工项(真机实测两条、签名仪式、TCC)顺延到新架构定型后再做。合并动作由用户执行(仓库无 remote,本 session 不代合)。
3. **「UI 不是必须」强度 = 一等公民**:内核 + CLI 可独立分发、全功能可用;唯 dangerous 在无确认代理时结构化默拒(`confirmation_unavailable` 类,fail-closed),确认代理可插拔——mac 端由菜单栏壳降格担任,其他端形态归 05 票。
4. **agent-first 裁决权重 = 分层**:安全底线(dangerous 需真人在场证明)> 法律义务(GPL 必须履行,落点可 CLI 化)> agent-first(压倒人类 UX:结构化输出、永不交互阻塞、GUI 只是内核的又一个客户端)> 人类便利。05/06 票直接引用此序。

Destination 措辞已按以上结论改写并经用户逐字确认(见地图)。
