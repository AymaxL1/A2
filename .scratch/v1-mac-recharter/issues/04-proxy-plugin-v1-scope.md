# 04 — 代理插件 V1 范围

Type: grilling
Status: resolved
Blocked by: 02, 05

## Question

代理插件（mihomo 壳、二进制随插件打包、V1 仅系统代理模式）的 V1 范围到底包含什么？待「mihomo 集成面与合规调研」与「Agent-first 接入面调研」落地后，用 `/grilling` 逐项定：

1. **生命周期**：App 退出时代理是否随之断开（无特权助手时内核随 App 生命周期，「退出即断」很可能是自然答案——确认用户接受）；崩溃后是否自动恢复系统代理设置，避免用户断网。
2. **功能面**：订阅管理深度（多 profile、自动更新、provider）；节点/代理组切换与延迟测速；流量/连接/日志展示到什么程度；规则编辑做不做（还是只读 profile）。
3. **UX 对标**：以 ClashX Meta 还是 Mihomo Party 的形态为参照——菜单栏轻壳 vs 完整控制中心页面，或两者组合。
4. **内核版本策略**：mihomo 版本随应用发布锁定，还是应用内可独立更新内核（结合调研票第 7 项的事实）。
5. **合规姿态**：根据调研票第 6 项的结论，决定应用的 license 姿态（是否开源、如何履行对 mihomo 的义务）。
6. **能力建模**：暴露给能力注册表/CLI/Agent 的能力面（例如 proxy.setMode、proxy.selectNode、proxy.status），哪些标 dangerous；这也是平台 dangerous 级权限模型的第一个真实用例。Agent 交互反转（地图前提 4）后，代理插件是 agent-first 的旗舰用例——用户的原话场景就是「让 Codex 调用我们设置 mihomo」；能力面设计须消费「Agent-first 接入面调研」的结论。

解决本票时产出可直接进 spec 的范围清单（in/out 两栏），并把新浮出的实施类问题交回地图（fog 或新票）。

## Answer

**决定（2026-07-28，用户裁决，四项均取推荐项）：**

**1. 壳形态与功能面：菜单栏轻壳（ClashX Meta 式对标）。** GUI 是能力面之上的薄壳；完整操作面走 CLI/capability（注册表唯一调用面，GUI 与 CLI 同源）。

- **In（V1）**：系统代理开关；模式切换（规则/全局/直连）；按代理组选节点；订阅管理（可存多个、同一时刻激活一个 profile、手动更新）；延迟测速（URL test，按组）；基础状态（内核运行状态/监听端口/当前模式与节点）。
- **Out（V1 不做）**：仪表盘大窗、流量图表、连接列表、日志查看器、规则编辑（profile 只读）、provider 高级特性、订阅定时自动更新、TUN（地图前提 2）。Mihomo Party 仅作后续版本功能路线参考，V1 不对标。

**2. 生命周期：退出即还原 + 崩溃自愈。** 正常退出：停 mihomo、把系统代理还原到接管前状态（退出=不再走代理）。崩溃/强杀：下次启动检测系统代理仍指向本应用端口时，自动恢复接管（内核拉起后重设）或还原，避免用户滞留「代理指向已死端口」的断网态；接管前快照的记录与检测细节归实施 spec。

**3. 能力分级（平台 dangerous 模型的第一个真实用例）：读=safe，改状态=normal，改信任面=dangerous。**

- **safe**（只读）：`proxy.status`、`proxy.groups.list`（组/节点/当前选中）、`proxy.latency.test`
- **normal**（可逆状态变更，菜单栏可见）：`proxy.system.enable|disable`、`proxy.mode.set`、`proxy.node.select`、`proxy.subscription.update`（仅已有源）
- **dangerous**（流量信任面变更，宿主 GUI 弹最终确认，agent/CLI 不能绕过）：新增/替换订阅源、直接覆写内核配置
- 旗舰场景验证：「Codex 帮我开代理/切节点」全程 normal 零 GUI 打断；「Codex 给我换订阅源」必经宿主确认。能力命名与 schema 的最终形态归「Swift 架构映射与工程形态」票的接口约定；本票定分级原则与清单粒度。

**4. 内核与合规：锁版 + 子进程隔离，宿主不开源（02 票结论全盘采纳）。** mihomo 随应用发布锁版（升内核=发应用更新，走 Sparkle 链），V1 不做应用内独立升内核；集成红线=只走子进程 + REST/外部 CLI，永不进程内链接；发布义务=发布物附 GPL-3.0 文本 + 内核版本与源码获取指引（关于页/发布说明）；宿主与插件代码闭源。内核重签+公证入统一构建链（落位归 07 票）。

**交回地图**：无新雾——实施细节（接管快照、REST 客户端、订阅存储）属「实施本身」（Out of scope），归代理插件 spec / 阶段路线（08 票）承接。
