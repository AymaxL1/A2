# 03 壳兜底浏览器的配置来源

Type: grilling
Status: resolved
Blocked by: —

## Question

铺图已裁:内核不可达时,壳做唯一一条机械兜底——把 URL 原样交给兜底浏览器(ADR 0008 红线的
显式豁免)。但壳从哪知道「兜底浏览器是谁」?候选:

- **壳直接读 `~/.a2` 配置文件** —— 简单,但壳跨界读内核配置域,格式耦合;
- **内核经 UDS 推送配置快照,壳内存缓存** —— 干净(壳只消费投影),但首次启动、内核从未
  跑过时缓存为空,仍需最终缺省;
- **壳侧硬编码缺省(Safari)+ 上述任一覆写** —— 保底永远有,代价是缺省写死在壳里。

要裁:取哪种(或组合);「最终缺省」是谁;这条豁免在 ADR 0008 修订里的措辞边界
(怎么写才能让「降级转发」不被后人读成「壳可以有逻辑」的口子)。

裁定结果并入 [06](06-spec-final.md) 的 spec 与 ADR 修订清单。

## Answer

裁定(2026-09-03,一轮 grilling,三问全清):

1. **兜底身份来源 = 持久化快照 + Safari 保底**。内核经既有 UDS「全量快照 + 增量推送」通道
   下发配置,兜底浏览器只是快照里多一个字段;壳把最后已知快照顺手存进自己的 UserDefaults
   (`com.a2.panel` 域)。兜底时取「最后已知快照」;连它都没有(壳从未收到过快照)时用硬编码
   `com.apple.Safari`(macOS 必有)。重启/内核宕机/`~/.a2` 被删,壳都能拿到用户真实兜底;
   壳**永不读** `~/.a2` 配置文件,无格式耦合。
2. **ADR 0008 豁免四条硬边界**(写进修订正文,突破任一即踩红线):
   ① 不解析 URL 内容;② 不做域名匹配;③ 唯一分支条件 = 内核可达与否(连接失败或超时);
   ④ 配置知识只来自内核推送快照,永不读内核文件。
   豁免定性:「哑管道 + 断电开关」—— 内核不可达时把 URL 原样交给最后已知兜底,
   是降级转发,不是决策。
3. **失效可见性 = 节流通知**。内核不可达后的**首次**兜底弹一条通知
   (「A2 内核未运行,链接已交给兜底浏览器」),后续静默;内核恢复(UDS 重连成功)后
   重置节流状态。规则纯机械、不看 URL,与四条边界相容。

并入 06 spec 的落点:配置快照新增字段、UserDefaults 键名、通知文案与节流状态机、
ADR 0008 修订措辞(四条边界原文)。
